--- title: API REST group: Referência desc: Autenticação por sessão e CSRF, endpoints por recurso, tempo real por SSE e exemplos com curl e Python. ---

A interface usa a mesma API pública que está documentada aqui, então tudo que a tela faz dá para automatizar. GET exige um usuário autenticado; qualquer outro método exige ADMIN. Erros voltam como JSON {"error": "..."} com o status HTTP adequado (400 para entrada inválida, 401 sem login, 403 sem permissão ou sem token CSRF, 404 e 409 conforme o caso).

Autenticação

A API usa cookie de sessão e proteção CSRF por double submit: o servidor entrega o cookie XSRF-TOKEN e você o devolve no cabeçalho X-XSRF-TOKEN em toda requisição que altera estado.

  1. Abra uma página (por exemplo /login.html) para receber o cookie XSRF-TOKEN.
  2. Envie POST /login com username e password (formulário) e o cabeçalho X-XSRF-TOKEN.
  3. O login renova o token: faça um GET /api/me para pegar o novo valor antes de qualquer POST.
BASE=http://127.0.0.1:8080
curl -s -c jar -b jar "$BASE/login.html" -o /dev/null
TOKEN=$(awk '/XSRF-TOKEN/ {print $7}' jar | tail -1)
curl -s -c jar -b jar -X POST "$BASE/login" -H "X-XSRF-TOKEN: $TOKEN" \
     -d 'username=admin&password=SUA-SENHA'
curl -s -c jar -b jar "$BASE/api/me" -o /dev/null          # o login renova o token CSRF
TOKEN=$(awk '/XSRF-TOKEN/ {print $7}' jar | tail -1)

# cadastrar um dispositivo
curl -s -b jar -X POST "$BASE/api/devices" -H "X-XSRF-TOKEN: $TOKEN" \
     -H 'Content-Type: application/json' \
     -d '{"name":"gateway","primaryIp":"192.168.1.1","deviceType":"ROUTER"}'

# listar
curl -s -b jar "$BASE/api/devices"

O mesmo em Python, só com a biblioteca padrão:

import json, urllib.request, urllib.parse, http.cookiejar

BASE = "http://127.0.0.1:8080"
jar = http.cookiejar.CookieJar()
op = urllib.request.build_opener(urllib.request.HTTPCookieProcessor(jar))
xsrf = lambda: next(c.value for c in jar if c.name == "XSRF-TOKEN")

op.open(BASE + "/login.html").read()
dados = urllib.parse.urlencode({"username": "admin", "password": "SUA-SENHA"}).encode()
op.open(urllib.request.Request(BASE + "/login", data=dados, headers={"X-XSRF-TOKEN": xsrf()})).read()
op.open(BASE + "/api/me").read()                      # renova o token

req = urllib.request.Request(BASE + "/api/devices", method="POST",
        data=json.dumps({"name": "gateway", "primaryIp": "192.168.1.1", "deviceType": "ROUTER"}).encode(),
        headers={"X-XSRF-TOKEN": xsrf(), "Content-Type": "application/json"})
print(json.load(op.open(req)))

Cada login derruba o token CSRF anterior; sessões abertas também são derrubadas quando o acesso do usuário muda (perfil, desativação, nova senha). Se receber 403 numa escrita, renove o token com um GET /api/me.

Tudo que é GET de Administração e Notificações também exige ADMIN, porque pode revelar a configuração. Um teste automatizado varre todas as rotas e garante isso.

Exemplos

Criar um perfil SNMP e rodar uma descoberta

# perfil v2c
curl -s -b jar -X POST "$BASE/api/snmp-profiles" -H "X-XSRF-TOKEN: $TOKEN" -H 'Content-Type: application/json' \
     -d '{"name":"Rede v2c","version":"2c","port":161,"timeoutMs":1500,"retries":1,"community":"public"}'

# varredura (authorized=true confirma que você pode varrer a faixa)
curl -s -b jar -X POST "$BASE/api/discovery/jobs" -H "X-XSRF-TOKEN: $TOKEN" -H 'Content-Type: application/json' \
     -d '{"cidr":"192.168.1.0/24","snmpProfileIds":[1],"ports":[22,80,443],"authorized":true}'

# acompanhar e listar os hosts
curl -s -b jar "$BASE/api/discovery/jobs/1"
curl -s -b jar "$BASE/api/discovery/jobs/1/hosts"

Importar hosts da descoberta

curl -s -b jar -X POST "$BASE/api/discovery/jobs/1/import" -H "X-XSRF-TOKEN: $TOKEN" -H 'Content-Type: application/json' \
     -d '{"hosts":[{"hostId":3,"name":"core-sw","deviceType":"SWITCH"}],"mapId":1,"openPortChecks":false}'

Criar um enlace manual

curl -s -b jar -X POST "$BASE/api/links" -H "X-XSRF-TOKEN: $TOKEN" -H 'Content-Type: application/json' \
     -d '{"sourceDeviceId":5,"targetDeviceId":12,"kind":"INTERNET","label":"Fibra 500 Mb"}'

Valores de kind: CABLE, WIFI, VPN, INTERNET, OTHER. Tipos de dispositivo (deviceType): ROUTER, SWITCH, FIREWALL, ACCESS_POINT, SERVER, WORKSTATION, PRINTER, STORAGE, CLOUD, NETWORK, OTHER.

Resumo para um painel externo

curl -s -b jar "$BASE/api/summary"

Tempo real (SSE)

GET /api/stream abre um fluxo Server-Sent Events (exige login). O servidor aceita até 500 conexões simultâneas. Eventos enviados:

EventoQuando
device-statusO estado de um dispositivo mudou.
eventUm novo evento foi registrado.
devices-changedDispositivos foram criados, editados ou removidos.
link-trafficNovas taxas de utilização dos enlaces.
discovery-progressProgresso de uma varredura.
 
curl -N -b jar "$BASE/api/stream"

Atrás de um proxy reverso, desligue o buffering para /api/stream, ou os eventos chegam em blocos atrasados (exemplo de nginx).
